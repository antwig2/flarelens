Connect servers and operator devices across different networks using **WireGuard**, encrypted peer-to-peer communication (`100.64.0.0/10`), and built-in private service discovery (`MagicDNS`).

## Zero-Config Peer-to-Peer WireGuard Overlay

On first startup, each `flarelensd` daemon generates an asymmetric Curve25519 keypair locally—the private key is stored `0600` on the host and never leaves the machine—and receives a deterministic CGNAT address in `100.64.0.0/10`.

The Control Plane distributes peer public keys and endpoints inside the 15-second heartbeat envelope so nodes form direct **ChaCha20-Poly1305 UDP tunnels**:

- **Zero Public Database Ports**: Keep PostgreSQL (`5432`) and Redis (`6379`) completely unexposed on public interfaces; bind them strictly to private interfaces and the WireGuard mesh.
- **Overlay Service Router (`<overlay_ip>:<mesh_port>`)**: Deterministic private listeners forward mesh traffic with zero-copy `io.Copy` round-robin across healthy local Blue/Green slots and remote peers.
- **Cross-Node Ingress Load Balancing**: Edge Traefik instances automatically balance HTTP requests across healthy container replicas on peer nodes via `remote_upstreams`.

## Split-Horizon MagicDNS (`<service>.<env>.mesh`)

`flarelensd` embeds a dual-stack **UDP + TCP** DNS server bound strictly to `<overlay_ip>:53` (avoiding conflicts with host `systemd-resolved` on `127.0.0.53:53`) and wires it into managed containers via Docker `HostConfig.DNS`:

```ini title="Container environment service discovery"
DATABASE_URL=postgres://app:secret@postgres.prod.mesh:5432/core?sslmode=require
REDIS_URL=redis://cache.prod.mesh:6379/0
BILLING_INTERNAL_URL=http://billing-api.prod.mesh:8080
```

- **`TTL = 5s` Round-Robin Failover**: Queries for `<service>.<env>.mesh` return lock-free round-robin A-records of healthy replicas with a 5-second TTL and RFC 4074 `NODATA` on `TypeAAAA`—so cross-host failovers propagate within seconds.
- **Strict Environment Isolation**: `uat` and `prod` DNS zones remain isolated (`postgres.uat.mesh` vs `postgres.prod.mesh`), and single-label misses return instant in-memory `NXDOMAIN` so internal names never leak upstream.
- **`ExtraHosts` Shadowing Guard**: When `<overlay_ip>:53` is active, static `100.64.0.0/10` entries are stripped from `/etc/hosts` so Linux `files dns` lookup order never shadows live `TTL 5s` failover, while retaining `/etc/hosts` fallback on non-WireGuard hosts.

## Operator Workstation Access

Join the private mesh temporarily from macOS or Linux workstations without SSH bastions or per-seat VPN SaaS:

```bash title="Authenticate operator workstation onto the mesh"
sudo flarelens-agent login --control https://ops.example.com

# Connect directly to private mesh services:
psql postgres://readonly@postgres.uat.mesh:5432/app

# Disconnect interface temporarily (keeps keys) or log out & revoke session:
sudo flarelens-agent down
sudo flarelens-agent logout
```

## Public HTTPS Localhost Funnel (`flarelensd http`)

Expose a local development server (`localhost:3000`, `localhost:8080`, Vite, Next.js, or webhook receiver) on a temporary public HTTPS URL—like `ngrok` or Tailscale Funnel, at **$0/mo** with zero third-party tunnel SaaS:

```bash title="Expose localhost:3000 on a public HTTPS subdomain"
# 1. Authenticate onto the mesh once (if not already connected)
sudo flarelensd login --control https://ops.example.com

# 2. Open a public HTTPS tunnel -> http://127.0.0.1:3000
flarelensd http 3000 --subdomain stripe-webhooks

# Optional: protect public preview with HTTP Basic Auth
flarelensd http 5173 --subdomain ui-preview --auth demo:s3cr3t
```

- **Zero LAN Exposure**: `flarelensd http` binds a local HTTP + WebSocket reverse proxy strictly on your workstation's `100.64.0.x` WireGuard interface—never `0.0.0.0`—and rewrites `Host: localhost:<port>` automatically while setting `X-Forwarded-Host` and `X-Forwarded-Proto: https`.
- **Keyless Ed25519 Ownership & Collision Guards**: Requests are signed with your workstation's `~/.flarelens/id_ed25519` key (`flarelens-mesh-tunnel:<action>:<wg_pub>:<ts>`). Active Fleet service domains cannot be overwritten (`409 Conflict`).
- **Automatic Cleanup**: Pressing `Ctrl+C` immediately deletes the D1 lease and removes `funnel-<id>.yaml` from the gateway node's Traefik directory; if a laptop disconnects abruptly, the 1-minute Control Plane cron reaps expired leases automatically.
