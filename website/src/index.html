Two-Plane Sovereign Design

The Edge Coordinates. Your Servers Own the Data Plane.

FlareLens never routes private database or container traffic through a central proxy. If control-plane connectivity ever drops, running containers, Traefik routes, and WireGuard tunnels continue serving live traffic autonomously.

Control Plane · Cloudflare Edge

Global Coordinator (antwig2/flarelens)

  • D1 State & Revisions: Immutable numbered fleet revisions (rev-1, rev-2, …), placement leases, and 1-click UAT → Prod promotion & rollback.
  • Piggybacked 15s Heartbeat: Commands, mesh peers, cluster endpoints, and feature flag hashes ride the /api/v1/ingest response (0 R2 list() calls).
  • AES-256-GCM Vault: Zero-plaintext secrets stored encrypted in Workers KV and delivered strictly into process RAM or ephemeral /dev/shm tmpfs.
  • Parquet Lakehouse: Compacts container logs into Hive-partitioned Apache Parquet in R2, queried in-browser via DuckDB-WASM with $0 egress.
▲ Outbound TLS / OIDC 15s Piggyback ▼ SHA-256 OTA
Data Plane · Cloud, Bare-Metal & Hybrid

Static Go Host Agent (antwig2/flarelensd)

  • Blue/Green & Singletons: Boots candidate slots, runs pre-deploy R2 pg_dump snapshots & migrations, verifies health probes, and flips Traefik in <1ms.
  • Hard Kernel Cgroups: Enforces HostConfig.Memory & NanoCPUs, updates running stateful singletons in place with zero restarts, and auto-prunes 72h+ images.
  • Direct P2P WireGuard: Kernel-space ChaCha20-Poly1305 mesh across regions and providers without central VPN relays or bandwidth bottlenecks.
  • Split-Horizon MagicDNS: Embedded UDP+TCP DNS server on <overlay_ip>:53 serving round-robin <service>.<env>.mesh records at TTL = 5s.
Platform Capabilities

Everything Docker Compose Was Missing Across Multiple Servers

No Kubernetes control-plane VMs, no etcd quorum babysitting, and no six separate SaaS subscriptions.

Zero-Git Fleet & Immutable Revisions

Create, edit, suspend, promote (uat → prod), and roll back workloads directly in the UI—or sync YAML manifests from GitHub Actions via keyless OIDC. Every mutation writes an immutable rev-N snapshot to D1 + R2.

Multi-Server Scheduler & Auto-Failover

Schedule stateless replicas across a server pool with spread anti-affinity, binpack consolidation, or pinned affinity. Drain nodes cleanly, reschedule off dead hosts automatically, and fence stateful DB volumes so data is never wiped.

Dynamic Mesh DNS (TTL 5s)

Containers receive HostConfig.Dns pointing to <overlay_ip>:53 over UDP and TCP. Cross-server calls to http://billing-api:8080 resolve across healthy WireGuard peers with lock-free round-robin and 5-second failover.

Zero-Plaintext Vault & RAM tmpfs

Secrets stay AES-256-GCM encrypted in KV until deployment, then inject into container memory or materialize into /dev/shm/flarelens-secrets (0700 host isolation, 0600 private keys) via __FLARELENS_FILE__—never touching persistent disks.

Hard Cgroup Limits & Auto Image Prune

Declare memory_mb and cpu_cores on apps, workers, and stateful singletons so a memory leak can never starve PostgreSQL. Retired Docker images older than 72 hours are garbage-collected automatically while preserving instant rollback layers.

Zero-Disk R2 Backups & DuckDB Logs

Pre-deploy guardrails stream gzipped pg_dump snapshots through an io.Pipe directly to Cloudflare R2 before running schema migrations, with automated rollback on failure and browser-native SQL analytics over Parquet logs.

Frequently Asked Questions

Common Architectural Questions

Do I need a GitOps repository to use FlareLens?

No. You can define, deploy, suspend, promote (uat → prod), and roll back services directly in the FlareLens Dashboard UI backed by immutable D1 + R2 revisions (rev-1, rev-2, …). If you also use CI/CD, GitHub Actions webhooks and fleet/*.yml OIDC syncs plug directly into the same revision history.

Does my private server-to-server traffic pass through Cloudflare?

Never. Cloudflare Workers only coordinates Curve25519 public keys and endpoint discovery. All private container, database, and operator mesh traffic flows directly peer-to-peer between your hosts over encrypted UDP WireGuard tunnels.

What happens if a host loses internet access to the Control Plane?

Running containers, local Traefik routing rules, hard kernel cgroups, and active peer-to-peer WireGuard sessions continue operating autonomously with zero disruption. Once connectivity returns, flarelensd resumes its 15-second heartbeat sync automatically.

Do I have to use Cloudflare Tunnel (cloudflared) for public web traffic?

No. FlareLens supports both direct public ingress (pointing standard A/AAAA DNS records at your server with Traefik/Caddy TLS) and zero-inbound-port tunnels (running cloudflared as a managed singleton with ports 22, 80, and 443 closed on your firewall).
