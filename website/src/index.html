ZERO-TRUST INFRASTRUCTURE

Every workload gets cgroup caps, no disk secrets, no open ports, and safe DB fencing.

Instead of scattering plaintext .env files and unguarded Docker sockets across VMs, FlareLens isolates resources in the kernel and keeps secrets strictly in volatile memory.

CGROUP CAPS

Hard Kernel RAM & CPU Isolation

Every Blue/Green slot, companion worker, and singleton enforces HostConfig.Memory and NanoCPUs. Running databases adopt updated cgroup ceilings live with zero restarts, and retired images auto-prune after 72h.

Cgroup & prune guide →
NO DISK SECRETS

Zero-Plaintext RAM Secrets

Secrets are encrypted at the Cloudflare edge with AES-256-GCM and injected directly into container process memory, while PEM/TLS/SQL files materialize inside a 0700 RAM-backed /dev/shm tmpfs mount.

Vault & RAM files →
NO OPEN PORTS

Direct P2P WireGuard & MagicDNS

Automatic Curve25519 peer discovery forms direct UDP tunnels (100.64.0.0/10) with an embedded split-horizon MagicDNSServer on <overlay_ip>:53 (TTL = 5s). East-west traffic never touches Cloudflare.

VOLUME FENCING

Stateful Fencing & R2 Snapshots

Draining or losing a node automatically reschedules stateless replicas onto healthy peers while fenced guardrails lock persistent Postgres/Dragonfly volumes and stream pre-migration pg_dump backups to R2.

GET STARTED

Deploy & enroll in 3 commands

# 1 · deploy control plane ($0 Cloudflare Free Tier)
git clone https://github.com/antwig2/flarelens.git && cd flarelens
npm install && npm run deploy
npx wrangler d1 migrations apply flarelens-control --remote

# 2 · enroll any Linux, bare-metal, or VPS server
curl -fsSL https://flarelens.dev/install.sh | sudo bash -s -- \
  --control https://control.example.com --token "$INGEST_SECRET"

# 3 · connect operator laptop to private *.mesh DNS
sudo flarelens-agent login --control=https://control.example.com

FAQ

Common architectural questions

Do I need a Git repository or cloudflared to use FlareLens?

Neither is required. You can create, promote, and roll back services natively in the FlareLens Dashboard (stored as immutable rev-N snapshots in D1 + R2), and expose public HTTPS either directly via DNS A/AAAA records + Traefik Let's Encrypt or via an optional zero-open-port cloudflared tunnel.

What happens to running traffic if Cloudflare Workers is unreachable?

Live traffic is completely unaffected. Containers, Traefik routers, cgroup limits, and direct peer-to-peer WireGuard tunnels run autonomously on your hosts; the control plane only coordinates changes, telemetry compaction, and peer discovery.

Can AI coding agents read all FlareLens docs and schemas at once?

Yes. Point Claude Code, Antigravity, Cursor, or Codex at https://flarelens.dev/llms-full.txt for the single-file Markdown documentation bundle, and reference https://flarelens.dev/schemas/fleet.schema.json in your YAML/JSON manifests for live IDE validation.
