Architecture

Designed for infrastructure you own.

A serverless control plane. A sovereign data plane.

Control plane — Cloudflare

Serverless Management

FlareLens uses Cloudflare Workers for its management API, D1 for operational state, KV for coordination and encrypted secrets, and R2 for log and backup storage.

Deploy it into your own Cloudflare account.

Execution plane — Your servers

Sovereign Runtime

A lightweight Go daemon manages workloads, deployments, host telemetry, and maintenance operations on enrolled machines.

Applications execute on your infrastructure, not inside the Cloudflare Worker.

Private network — WireGuard

Direct Peer-to-Peer Mesh

WireGuard establishes encrypted connections between participating hosts and operators.

Cloudflare coordinates management and peer discovery without acting as the default router for private workload traffic.

Declarative State

Declarative deployments without mandatory GitOps.

Define what should run. FlareLens works to keep it running.

Create a service from the dashboard, configure its runtime and placement requirements, and save it as an immutable revision.

FlareLens compares the declared configuration with the observed infrastructure and reconciles differences.

Promote configurations between environments, inspect revision history, and restore an earlier version when necessary.

Use the dashboard directly, or integrate your existing Git and CI/CD workflows.

Your workflow. Your choice.

Declarative workload specification fleet.schema.json 
# yaml-language-server: $schema=https://flarelens.dev/schemas/fleet.schema.json
service: billing-api
env: prod
mode: blue_green
domain: api.example.com
image: ghcr.io/acme/billing-api:1.4.0
replicas: 2
placement_strategy: spread
memory_mb: 512
cpu_cores: 1.0
container_port: 8080
host_port_blue: 9080
host_port_green: 9081
health_path: /health
pre_deploy_snapshot: true
networks:
  - app-prod
  - flarelens-edge

FAQ

Frequently asked questions

Do I need Kubernetes?

No. FlareLens provides its own declarative fleet and container deployment capabilities without requiring a Kubernetes cluster.

Do I need a Git repository?

No. You can define and manage services from the FlareLens dashboard. Git and CI/CD integrations are optional.

Do I need Cloudflare Tunnel?

No. Direct ingress through Traefik or Caddy is supported. Cloudflare Tunnel is an optional deployment choice.

Where do my applications run?

On your enrolled servers. Cloudflare hosts the control plane, not your application containers.

Is FlareLens free?

FlareLens is open-source software. Its control plane is designed to run within Cloudflare's free-tier allowances for smaller deployments. Usage exceeding free-tier limits and the underlying compute or storage infrastructure may incur charges.

What happens if the control plane is unavailable?

Existing applications continue running on their hosts. Management operations, reconciliation, and other functions requiring connectivity may be delayed until the control plane becomes available.
