1. Getting started ($0 Cloudflare Free Tier)

Click Deploy to Cloudflare Workers or deploy with Wrangler v4, which automatically provisions CONTROL_DB (D1), FLEET_KV (KV), LOGS_BUCKET (R2), and BACKUP_BUCKET (R2).

2. Host agent (flarelensd)

Enroll any Linux VM or bare-metal server in one command. The installer verifies the binary SHA-256 digest, writes /etc/flarelens/agent.toml, and starts flarelensd.service. Future binary upgrades roll out over-the-air (self_update) with zero SSH.

3. Zero-Git declarative fleet & revisions

Create Blue/Green apps or stateful singletons directly in the web UI or sync YAML manifests from CI. Every mutation writes an immutable numbered snapshot (rev-1, rev-2, …) to D1 and R2 (state/revisions/rev-N.json) supporting 1-click uat → prod promotion and 1-click rollback.

4. WireGuard P2P mesh & split-horizon MagicDNS

  • Direct P2P Overlay: Curve25519 keys are exchanged over heartbeats while all east-west container and database traffic flows directly host-to-host over WireGuard UDP (100.64.0.0/10).
  • 5-Second MagicDNSServer: Binds strictly to <overlay_ip>:53 (UDP + TCP), serving lock-free round-robin A records for <service>.<env>.mesh with TTL = 5s and stripping CGNAT entries from static /etc/hosts so failover is never shadowed by libc file order.
  • Drain & Volume Fencing: POST /api/v1/control/nodes/:id/drain evacuates stateless replicas while marking stateful database volumes fenced so local NVMe data is never auto-wiped.

5. Blue/Green rollouts & schema migrations

Every Blue/Green rollout executes a deterministic 7-stage pipeline: R2 database snapshot guardrail → image pull → ephemeral migration container → candidate slot boot → HTTP health probe gate → sub-millisecond Traefik dynamic file swap → graceful connection drain (with automatic DB snapshot restore if migrations fail).

6. Zero-plaintext Vault & RAM secret files

Prefix any Vault secret or env_vars entry with __FLARELENS_FILE__ to materialize certificates, private keys, SQL init scripts, or config files directly into a 0700 RAM-backed /dev/shm/flarelens-secrets mount (0600 on private keys, 0644 on SQL/YAML/public certs for non-root container UIDs):

7. Hard kernel cgroups & automatic image prune

memory_mb and cpu_cores enforce hard Linux kernel HostConfig.Memory and NanoCPUs caps. Reconciling a running stateful singleton (postgres, dragonfly) applies updated cgroup limits in place via POST /containers/{id}/update with zero restarts. Retired Docker images are pruned in two passes (dangling >24h, unused tagged >72h).

8. R2 Parquet log lakehouse & streaming backups

Logs are compacted into Snappy-compressed Apache Parquet partitions on Cloudflare R2 and queried in-browser with DuckDB-WASM over HTTP range requests ($0 egress). Database backups stream pg_dump | gzip straight through an in-memory io.Pipe to R2 with zero temporary disk usage.
