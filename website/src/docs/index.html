Platform Documentation

Deploy the serverless Cloudflare Workers + D1 + R2 control plane in under two minutes, enroll Linux/macOS/Windows servers with a single command, and orchestrate zero-downtime multi-node workloads.

1. Deploy the Control Plane ($0 Free Tier)

Wrangler v4 automatically provisions your CONTROL_DB (D1), FLEET_KV (Workers KV), LOGS_BUCKET (R2), and BACKUP_BUCKET (R2) bindings directly from wrangler.toml.

2. Enroll Server Nodes (flarelensd)

Install the static Go host daemon directly from https://flarelens.dev/install.sh (or your own Worker URL). The installer verifies SHA-256 digests, writes /etc/flarelens/agent.toml, and enables the flarelensd.service systemd unit.

3. Zero-Git Declarative Fleet & Immutable Revisions

Open Declarative Fleet in your dashboard and click + New Service to launch Blue/Green apps or stateful singletons (postgres, dragonfly, traefik, cloudflared). Every save writes an immutable revision (rev-1, rev-2, …) to D1 and R2 with 1-click uat → prod promotion and 1-click rollback.

4. Multi-Server Scheduling, Drain Fencing & Dynamic Mesh DNS

  • Placement Strategies: spread (HA anti-affinity across distinct hosts), binpack (pack onto highest-utilization fitting nodes), or pinned (node_id / required_tags).
  • Split-Horizon MagicDNSServer (TTL = 5s): Binds strictly to <overlay_ip>:53 over UDP and TCP (RFC 1035 2-byte framing), serving round-robin A records for <service>.<env>.mesh across all healthy WireGuard replicas while stripping CGNAT entries from static /etc/hosts so failover happens within 5 seconds.
  • Graceful Node Drain & Stateful Fencing: POST /api/v1/control/nodes/:id/drain migrates stateless replicas to peer servers while marking stateful volume workloads as fenced so local database disks are never wiped automatically.

5. Hard Docker Cgroup Isolation & Auto Image Prune

Setting memory_mb and cpu_cores configures both the Control Plane capacity scheduler and Linux kernel cgroups (HostConfig.Memory and HostConfig.NanoCPUs) across Blue/Green slots, companion workers, and singletons.

  • Zero-Restart Singleton Cgroup Sync: Updating memory_mb or cpu_cores on a running postgres or dragonfly singleton applies live via Docker's POST /containers/{id}/update API without restarting the database.
  • Two-Pass Image Garbage Collection: Automatically prunes dangling images older than 24h and unused tagged images older than 72h after deployments and on a 12-hour daemon schedule (preserving 72 hours of instant local rollback cache).

6. Zero-Plaintext Vault & Ephemeral RAM Secret Files

Store per-service environment secrets in the Dashboard Vault (encrypted at the edge with AES-256-GCM). To mount private PEM keys, SQL init scripts, or config YAML files without writing them to persistent host disks, prefix any Vault or env_vars key with __FLARELENS_FILE__:

flarelensd enforces 0700 root-only host isolation on /dev/shm/flarelens-secrets, sets 0600 on private keys (*.key, *priv*.pem) and 0644 on SQL/YAML/public certs so non-root container UIDs (like postgres UID 999) read them seamlessly, and auto-bootstraps missing persistent read-write data directories.

7. Streaming R2 Snapshots & Parquet Log Lakehouse

  • Zero-Disk Pre-Deploy Snapshots: When pre_deploy_snapshot: true or run_migrations: true is set, flarelensd streams pg_dump | gzip straight to Cloudflare R2 via an in-memory io.Pipe before running schema migrations, automatically restoring the snapshot if migrations fail.
  • Columnar Parquet Log Lakehouse: Logs are compacted into Snappy-compressed Apache Parquet partitions in R2 and queried directly in the browser with DuckDB-WASM for sub-second SQL analytics with $0 egress fees.

8. Canonical JSON Schema & Control Plane Endpoints

  • Canonical Schema URL: https://flarelens.dev/schemas/fleet.schema.json
  • Host Installer Script: https://flarelens.dev/install.sh (PowerShell: /install.ps1)
  • POST /api/v1/ingest — Authenticated 15s agent telemetry ingest & piggybacked command/mesh/flag sync
  • POST /api/v1/control/fleet/sync — Keyless GitHub OIDC or Bearer declarative fleet sync
  • POST /api/v1/control/fleet/promote & POST /api/v1/control/fleet/rollback — Environment promotion & revision rollback
  • POST /api/v1/control/nodes/:id/drain, /uncordon, & /prune-images — Host lifecycle operations
