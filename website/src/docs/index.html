Serverless Infrastructure Control Plane

FlareLens Documentation

Deploy an open-source infrastructure control plane into your own Cloudflare account, enroll host machines with flarelensd, and manage deployments, private networking, secrets, and observability from one place.

1. Deploy Your Control Plane

Launch FlareLens in your own Cloudflare account using the Deploy to Cloudflare button—Wrangler v4 provisions CONTROL_DB (D1), FLEET_KV (KV), LOGS_BUCKET (R2), and BACKUP_BUCKET (R2)—or deploy from the command line:

Deploy Control Plane via Wrangler CLI sh 
git clone https://github.com/antwig2/flarelens.git
cd flarelens
npm install

npx wrangler secret put INGEST_SECRET
npx wrangler secret put DASHBOARD_PASSWORD
npx wrangler secret put VAULT_MASTER_KEY

npm run deploy
npx wrangler d1 migrations apply flarelens-control --remote

2. Connect Your Servers (flarelensd)

Install the Go host daemon (antwig2/flarelensd) using https://flarelens.dev/install.sh (Linux/macOS) or https://flarelens.dev/install.ps1 (Windows):

Enroll a Linux or macOS host sh 
curl -fsSL https://flarelens.dev/install.sh | sudo bash -s -- \
  --control "https://your-control-plane.workers.dev" \
  --token ""
Over-the-air agent updates: Enrolled hosts verify SHA-256 checksums and apply binary upgrades via self_update commands delivered over the 15-second heartbeat, waiting for active deployments or backups to complete before restarting.

3. Declarative Workloads Without Mandatory GitOps

Define applications directly in the dashboard or synchronize YAML/JSON manifests through CI/CD:

  • Immutable Revisions: Every configuration change is recorded as a numbered revision (rev-1, rev-2, …) in D1 and R2.
  • Promotion & Rollback: Promote verified builds between environments (such as uat to prod) and restore earlier revisions—including deleted services—when needed.
  • Staged Activation (enabled: false): Prepare production manifests in a suspended state while configuring secrets, then activate them when ready.

4. Placement, Cgroup Limits & Stateful Safety

Validate manifests against https://flarelens.dev/schemas/fleet.schema.json:

  • mode: blue_green (health-checked Blue/Green slot releases) or singleton (stateful services such as PostgreSQL, Dragonfly, Redis, or ingress proxies).
  • placement_strategy: spread (distribute replicas across hosts), binpack (consolidate capacity), or pinned (target a specific host), with optional required_tags.
  • memory_mb & cpu_cores: Enforces Linux kernel cgroup limits (HostConfig.Memory and NanoCPUs) across containers and companion workers, with live in-place updates on running stateful singletons.
  • Volume Fencing: Draining a host reschedules stateless replicas onto healthy servers while fencing local stateful volumes so persistent database files are preserved.

5. Private WireGuard Network & Service Discovery

Enrolled servers and operator workstations form an encrypted peer-to-peer WireGuard network (100.64.0.0/10) without routing workload traffic through Cloudflare:

  1. Overlay Service Forwarding: Deterministic WireGuard overlay ports route cross-server requests to active local container slots.
  2. Embedded Mesh DNS (TTL 5s): Each host runs a split-horizon UDP+TCP DNS listener on its private WireGuard address, resolving <service>.<env>.mesh across healthy peers with automatic ExtraHosts fallback when needed.

6. Secrets & Runtime Configuration

  • Encrypted Storage: Secrets are encrypted with AES-256-GCM in Workers KV and injected into container process memory at launch rather than written as persistent .env files.
  • Ephemeral RAM Files: Entries prefixed with __FLARELENS_FILE__/container/path materialize into /dev/shm/flarelens-secrets (0700 host root, 0600 private keys) for certificates, keys, and bootstrap scripts.

7. Backups & Observability

  • Streaming PostgreSQL Backups: Pre-deploy guardrails and scheduled jobs stream compressed pg_dump archives directly to Cloudflare R2 without writing large temporary files to local disks.
  • Parquet Log Retention: Host and container telemetry is stored in compressed Apache Parquet partitions in R2 for inspection alongside live log streams.

8. Management API Summary

Core FlareLens Control Plane HTTP endpoints
Method Endpoint Auth Purpose
POST /api/v1/ingest Bearer Ingest Token Host telemetry ingestion and piggybacked command, peer, and endpoint sync
POST /api/v1/control/fleet/sync Bearer / GitHub OIDC Validate and reconcile declarative manifests into an immutable revision
POST /api/v1/control/fleet/promote Admin Session / Token Promote verified service configurations between environments
POST /api/v1/control/fleet/rollback Admin Session / Token Restore fleet state to an earlier numbered revision
POST /api/v1/control/nodes/:id/drain Admin Session / Token Cordon a host, reschedule stateless workloads, and fence stateful volumes
GET /schemas/fleet.schema.json Public JSON Schema Draft-07 for manifest validation and editor autocomplete
